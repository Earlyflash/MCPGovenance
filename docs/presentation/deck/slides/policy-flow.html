How a policy becomes a guardrail

1

Compliance writes policy

In plain language, on the docs site.

2

Turned into a rule

Guidance in YAML, plus a detector if it can be automated.

3

Governance approves

A pull request that the owning team must approve.

4

Live everywhere

Every pull request is checked from its next run.

Exceptions: a waiver file in the product’s repo, approved by the governance team through code owners. Dated, narrow and visible.

About 1 minute. Be precise here, because it is a common misunderstanding: the guidance is mostly YAML, not code. Code is needed only where a rule can be checked automatically, and then it is a small detector. A waiver is approved once but it expires, after at most 90 days, and it covers every matching finding in its path for that time, so approvers should insist on narrow paths. Be honest that the code owner approval only becomes enforced when a branch ruleset requires it, which is not set up yet in the proof of concept.
